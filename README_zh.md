## 核心价值：为什么需要 Anchor？

使用终端编程智能体（Claude Code、Pi、Aider 等）结对开发时，开发者普遍面临三个具体痛点：

### 1. 终端一关即失忆（Session Amnesia）
按下 `Ctrl+C` 退出终端，Agent 内存中的上下文被清空。未完成的代码重构计划、临时交代的排期与多步约定随之丢失。

### 2. TODO.md 污染 Git 且拖垮上下文
在工程根目录下维护 `TODO.md` 或 `AGENTS.md`：
- 会产生大量 `update todo`、`fix checklist` 之类的 Git 杂质提交；
- **每一轮对话都要把几十行陈旧清单塞入 System Prompt**，白白消耗大量 Token 预算，还会分散模型对当前核心代码的注意力。

### 3. 告别手动打勾与清单发霉
写完代码后，工程师极少会专程打开 Markdown 逐个打勾。未勾选的旧任务烂在仓库里，越积越多。
现存的第三方方案走向了重型极端（例如 `beads` 往代码仓库塞入 200MB 的 Dolt SQL 数据库，`engram` 启动常驻后台的 Go 守护进程与向量检索库）。

**Anchor 采取了克制而轻量的工程解法**：
- **零仓库污染**：任务状态保存在全局主目录 `~/.anchor/state.json`，项目 Git 历史 100% 纯净；
- **0 闲置 Token 损耗**：第 1 轮冷启动注入任务，第 2 轮起保持 0 Token 稳态，绝不浪费推理预算；
- **语法安全 JIT 唤醒**：Agent 触碰相关代码文件时，以对应语言的单行安全注释精准唤醒，严格跳过 JSON、ENV 与锁文件；
- **自动核销与防误触抽屉**：代码提交命中任务描述或退出终端时自动核销；交互式面板提供防误触二级菜单。

## 核心特性与 v0.2.1 加固机制

### 1. 绝对零仓库污染与跨进程文件锁
所有状态统一保存在用户主目录 `~/.anchor/`，项目内绝不创建任何 `.anchor` 目录：
```text
~/.anchor/
├── state.json           # 活跃与休眠任务状态表 (< 10KB，原子写入)
├── state.lock           # 跨进程纯同步原子排他锁 (零依赖)
├── archive.jsonl        # 已完成归档的历史账本 (追加写入)
└── graveyard.jsonl      # 超期脱落墓地账本 (追加写入)
```
* **零依赖排他锁**：使用 Node 原生 `fs.openSync` 保证多终端并发读写安全；
* **死锁自动熔断回收**：若持有锁的进程已终止或超时（5000ms），系统自动安全回收重占；
* **原子写入与崩溃自愈**：写入临时文件后执行原子重命名，带 Windows NTFS 自旋重试。损坏文件自动备份为 `state.corrupt.${timestamp}.json` 并安全回退。

### 2. 防误触结算抽屉与详情查看器 (v0.2.1)
在 `/anchor` 仪表盘中选中任务后，弹出二级操作菜单：
* `✓ Settle (完成归档)`：核销并归档任务，提示可通过 `/anchor undo` 撤销恢复；
* `ℹ View details & associated files`：直接在终端查看完整任务描述、目标日期、关联文件列表与自动化物理验证命令；
* `↩ Cancel`：安全取消退出，避免直接敲击回车意外核销未完成事项。

### 3. 截断开括号守卫 (v0.2.1 · Invariant 11)
在仪表盘字符串视觉列宽截断算法中，自动清除省略号前紧邻的孤立未闭合开括号（`(`、`[`、`{`、`（`、`【`），消除标点破裂与视觉毛刺。

### 4. 0-Token 稳态经济与多语言语法安全 JIT
* **第 1 轮冷启动**：注入当前工作区的活跃任务承诺与简要行动指南；
* **第 2 轮起 0 损耗**：任务清单从 System Prompt 中彻底脱敏移除，普通写代码轮次消耗 **0 Token**；
* **语法安全严格跳过**：根据文件扩展名动态生成合法单行注释（`//`, `#`, `<!-- -->`, `/* */`）。对 **JSON、ENV、Lockfile 与二进制文件坚决返回 null 严格跳过**，杜绝破坏代码解析器。

### 5. 冷启动前置物理执行验证
任务声明 `verifyCommand` 时，系统在启动时自动执行该物理命令。验证通过的任务即刻就地核销，释放认知带宽。

## 常用命令

### 命令行速查
```bash
anchor                                  # 查看活跃任务列表（Neovim 极客排版）
anchor "重构鉴权模块"                   # 快速立项新任务
anchor "提交实证报告" --due friday      # 指定周五到期
anchor done 1                           # 完成第 1 行任务（支持连续编号）
anchor done anc-5                       # 按具体 ID 完成任务
anchor undo                             # 撤销上一次完成归档
```

### Pi 扩展内交互命令
| 命令 | 说明 |
| :--- | :--- |
| `/pin "任务描述"` | 快速立项当前工程的跨会话任务 |
| `/anchor` | 在终端内弹出全景交互式任务仪表盘 |
| 状态栏 `⌖ N` | 底部常驻微标签，有活跃任务时显示数量，无任务时 100% 静默隐形 |

| 核心维度 | `gastownhall/beads` | `Gentleman-Programming/engram` | `TODO.md` / `AGENTS.md` | **Anchor ⚓** |
| :--- | :--- | :--- | :--- | :--- |
| **架构拓扑** | 分布式 SQL 图谱 | 向量检索与 SQLite 常驻进程 | 静态 Markdown 文件 | **轻量解耦协议 + 单文件原子状态机** |
| **仓库整洁度** | 塞入 200MB Dolt 数据库 | 系统常驻守护进程 | 频繁制造 Git 提交杂质 | **100% 零仓库污染 (`~/.anchor/`)** |
| **每轮 Token 开销** | 中高频次全量注入 | 高 (全量提示词召回) | 严重 (陈旧清单持续膨胀) | **0 Token 稳态 (仅在触碰文件时 JIT 唤醒)** |
| **语法注入安全** | 无安全机制 | 原始文本直接拼接 | 静态未格式化文本 | **多语言语法安全注释，JSON/ENV 严格跳过** |
| **任务结算与核销** | 手动命令 `close` | 无自动结算机制 | 人工修改文本打勾 | **Git Commit 自动识别 + 退出前一键核销** |
| **并发读写安全** | SQL 事务排他锁 | 守护进程单点调度 | Git 合并冲突频繁 | **零外部依赖 Node 原生原子排他文件锁** |
| **启动性能损耗** | 较重 CLI 引导 | Go 进程通信延迟 | 无损耗 | **< 90ms 轻量打包生产产物** |
| **底层运行依赖** | 外部 Dolt 二进制 | 外部 Go 二进制 | 无依赖 | **零原生二进制外部依赖 (纯 TypeScript)** |

## 作者手记 (Author's Note)

写 Anchor 的最初冲动，来自于我用终端 AI 编程智能体结对开发时经历的一场持续阵痛：看着项目根目录下的 `TODO.md` 与 `AGENTS.md` 在 Git 历史里发霉。

很多时候，写完一段代码已经是深夜，跨会话未完成的任务随手记在项目的 Markdown 里，看起来省事。然而几个月下来，两点物理摩擦让我极其痛苦：
1. 每一轮对话交互，AI 都要把陈旧的任务清单整段塞进系统提示词，白白烧掉几十上百行 Token，还会分散模型对当前正在修改的代码的注意力；
2. 团队多人协作或分支合并时，这类任务清单文件频发 Git 合并冲突，无端污染了核心代码的提交历史。

调研现存工具时，我发现社区给出的方案走向了沉重的极端：为了管理几个简单的任务，有的方案直接在代码仓库根目录塞入一个超过 200MB 的 Dolt SQL 关系型数据库（`beads`），有的方案在后台常驻一个用 Go 编写的 SQLite 守护进程并做持续向量检索（`engram`）。一个任务追踪工具消耗的系统资源与认知负担，甚至超过了开发者正在编写的业务代码本身。

这颠倒了工具与生产者的关系。

Anchor 选择了一条极度克制的工程路径：把状态移出代码仓库，托管在用户主目录下的单文件轻量状态表（`~/.anchor/state.json`）；首轮对话注入冷启动上下文，第 2 轮起保持 0 Token 损耗；通过语言对应的语法安全注释在触碰代码时精准唤醒，并在代码提交或会话退出时自动核销。

在 v0.2.1 中，我们还为 `/anchor` 增加了防误触详情面板，按回车可以从容查看关联文件与执行命令，并在排版算法中消除了开括号截断毛刺。

希望 Anchor 能让你的代码仓库保持干净，把专注力还给代码本身。
